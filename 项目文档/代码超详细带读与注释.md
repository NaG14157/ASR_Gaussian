## 0. 先记住这件事：项目要解决什么问题

这是一个**光场角度超分辨率**项目。光场由多个略有视差的视角组成，可把每个视角看成一张小图。输入是四个角视角组成的 `2×2` 图像阵列，网络预测目标阵列中间缺失的视角。

这里的“超分”主要发生在**角度维度**：默认从 `2×2` 个输入视角生成 `7×7` 个输出视角。每个视角的像素高度、宽度通常不变（默认 `upscale_factor=1`）。输入和输出都以 SAI（Sub-Aperture Image）形式存储：把小视角图按角坐标拼成一张大图。

以单视角 `64×64`、批量大小 `B=1` 为例：

| 对象 | 逻辑视角数 | SAI 张量形状（不含批次/通道时） |
|---|---:|---:|
| 输入 `data` | `2×2` | `128×128` |
| 标签 `label` | `7×7` | `448×448` |
| 网络输出 `out` | `7×7` | `448×448` |

网络最后会把输入的四个角像素块原样放回输出，所以训练损失重点只计算其余 `7×7−4=45` 个缺失视角。

### 阅读时经常出现的维度记号

- `B`：批次大小；`C`：特征通道，主干通常是 64。
- `u,v`：两个角坐标轴；`s,t`：单个视角内的空间坐标轴。
- SAI 通常是 `[B, C, angRes×H, angRes×W]`；拆开角度后常写成 `[B,C,u,v,H,W]`。
- PyTorch 卷积输入常见布局是 `[B,C,D,H,W]`（3D 卷积）或 `[B,C,H,W]`（2D 卷积）。`permute`/`rearrange` 主要是在改变维度解释与排列，不一定改变数据本身。

## 2. 一次训练样本的旅程

### 2.1 读 HDF5：`TrainSetLoaderRawLF`

训练集 Dataset 按目录列出样本文件。`__getitem__` 打开对应 `.h5`，取 `raw_lf_key`（默认 `label`）下的二维 SAI 数组，再用 `ToTensor()` 转成 PyTorch 张量。

关键点：这个 Dataset 读入的是完整角度光场，不在这里拆成输入和标签。训练时才根据本轮采样到的目标角分辨率裁切，因此同一个原始样本可以在线产生不同角度规模的监督对。

### 2.2 在线中心裁切：`crop_lf_sai`

假设原始光场是 `9×9` 视角，每个视角 `64×64`，整个 SAI 为 `576×576`。如果本轮 `angout=7`，函数会以视角为单位，从 `9×9` 阵列中央裁出 `7×7`，对应 SAI 的中心 `448×448` 区域。

这里裁的是**角度阵列的边缘视角**，不是把每张 `64×64` 小图裁小。每个视角的空间像素尺寸仍然保持原样。

伪代码：

```python
patch_h = height // source_ang_res  # 一张视角图的高度
start = (source_ang_res - angout) // 2
label = raw_lf[..., start*patch_h : (start+angout)*patch_h, ...]
```

`crop_policy` 目前只接受 `center_floor`，传入其他策略会报错。这是显式校验，避免悄悄按错误规则裁切。

### 2.3 从标签抽四角：`build_input_from_cropped_label`

函数把裁出的标签 SAI 分成 `angout×angout` 个小块，然后取左上、右上、左下、右下四块，再按 2×2 顺序拼成输入 SAI。

```text
label 的角视图布局（例如 7×7）：
  ●  ·  ·  ·  ·  ·  ●
  ·  ·  ·  ·  ·  ·  ·
  ·  ·  ·  ·  ·  ·  ·
  ·  ·  ·  ·  ·  ·  ·
  ·  ·  ·  ·  ·  ·  ·
  ·  ·  ·  ·  ·  ·  ·
  ●  ·  ·  ·  ·  ·  ●

● = 输入已知的四个角视角；· = 网络需要预测的视角
```

因此，训练输入和标签的四角完全来自同一组像素。这也解释了为什么模型会把四角直接复制回输出，以及为什么损失掩码要排除四角。

`make_online_crop_pair` 把以上两步组合起来，返回 `(data, label)`。在训练循环中，这就是原始样本到监督样本的转换点。

### 2.4 训练模式与增强

`training_policy.py` 定义两种策略：

- `ARBITRARY_SCALE_MODE=1`：每个训练样本从 `[angout_min, angout_max]` 随机抽一个 `angout`。策略函数不启用几何/缩放增强，重点是让模型见到不同输出角分辨率。
- `FIXED_SCALE_MODE=2`：固定使用 `angout`，并启用 `augmentation_with_resize`。默认配置是固定 7×7 微调。

`validate_training_policy` 在开始训练前检查 `source_ang_res`、`angout` 区间合法性。目标角分辨率至少为 3，因为 2×2 只有已知四角，没有缺失视角可学；目标也不能大于原始源光场角分辨率。

`data_augmentation.py` 对输入与标签始终做**同步变换**：水平翻转、垂直翻转、转置会同时作用于两者，以保持监督对应关系。`resize_sai_center_zoom` 则逐个视角截取中心区域并双线性放大回原尺寸；它是视角内部的空间增强，不能和角度裁切混为一谈。文件提供 NumPy 与 Torch 路径：前者可处理 NumPy 数组，后者适用于训练张量。

## 3. 训练入口与训练循环：`train.py`

### 3.1 `parse_args()`：命令行配置

这个函数定义训练所需参数：设备、输入/输出角分辨率、训练模式、数据目录、优化器参数、预训练权重、验证保存选项，以及高斯解码器相关开关。

几个容易混淆的参数：

- `--angin`：输入角分辨率，当前网络数据准备只支持 `2`。
- `--angout`：固定模式的目标角分辨率；任意尺度模式使用 `--angout_min/--angout_max`。
- `--source_ang_res`：训练 HDF5 原始光场包含的视角边长，例如 9。
- `--load_pretrain` / `--weights_only_pretrain`：是否载入已有 checkpoint；后者决定只载入模型参数还是尝试恢复优化器和 scheduler 状态。
- `--ablate_planes`：实验性地关闭一个或多个体积支路，合法名为 `uvs, uvt, ust, vst`。

文件开头会根据可选命令行参数设置 `CUDA_VISIBLE_DEVICES`。这类环境变量必须在 CUDA 初始化之前设置，因此代码尽量把设置动作放在 `import torch` 之前。

### 3.2 `main(cfg)`：把组件装起来

入口大致做这些事：

1. 校验训练策略和数据参数。
2. 建训练 Dataset/DataLoader；训练 DataLoader 的 batch 默认是 1。
3. 调用 `MultiTestSetDataLoader` 为测试根目录下的各个子目录分别建验证 loader。
4. 准备输出目录、TensorBoard writer。
5. 调用 `train(cfg, train_loader, test_Names, test_loaders)`。

测试数据加载器使用固定的 `data` 和 `label` 键。当前 Dataset 代码还会对这两个数组做 `(1,0)` 转置，再转 Tensor；准备测试 HDF5 时必须符合该存储约定。训练原始光场读取没有这一步转置。

### 3.3 `train(...)`：模型、优化器与恢复权重

函数首先创建 `Net_CrossAttention`，把模板、高斯偏移和置信门控等配置传进模型。若机器上有多张 CUDA 卡，则包装为 `DataParallel`。之后建立 Adam 优化器和 StepLR 学习率调度器。

预训练加载分两层：

1. `filter_pretrain_state_dict` 去掉旧权重键名前缀 `module.`，只保留当前模型中**键名存在且形状相同**的张量。这样模型结构有少量变化时仍可加载兼容部分。
2. `strict=False` 加载后打印未匹配键。只有权重兼容且没有被配置为 weights-only 时，代码才尝试恢复 optimizer/scheduler/epoch。老 checkpoint 缺少新加的 `confidence_net` 时会退回仅载权重，避免恢复不兼容的优化器状态。

### 3.4 每个 batch 的核心代码逐句解释

训练循环可以压缩成如下阅读版：

```python
raw_lf = batch
angout = resolve_training_angout(...)       # 固定或随机决定本样本输出角分辨率
data, label = make_online_crop_pair(...)    # 从原始光场生成 2×2 输入和目标标签
data, label = apply_training_augmentation(...) # 按模式同步增强
data, label = data.to(device), label.to(device)
out = net(data, angout)                     # 前向：输出 angout×angout SAI
base_l1 = missing_view_l1_loss(out, label, angout)
grad_loss = missing_view_sobel_gradient_loss(out, label, angout)  # warmup 后启用
loss = base_l1 + grad_lambda_current * grad_loss
optimizer.zero_grad()
loss.backward()
optimizer.step()
```

`resolve_training_angout` 是运行时选择目标角分辨率的地方；`net(data, angout)` 把这个值显式传给网络，所以一次模型前向可以指定输出角度规模。

梯度损失采用 warmup + ramp：前 `grad_l1_warmup_epochs` 个 epoch 权重为 0，接下来 `grad_l1_ramp_epochs` 个 epoch 线性升到 `grad_l1_lambda`。当权重为 0 时，代码不计算 Sobel 损失，而创建一个与 `base_l1` 同设备/类型的零标量。

每个 epoch 末尾会汇总总损失、L1、梯度损失和四个体积的平均门控比例；写入日志/TensorBoard，执行 `scheduler.step()`，并通过 `build_training_checkpoint` 保存模型、优化器、调度器、epoch 与 loss 历史。

注意：本版本训练循环开头会先用验证 loader 做一次验证；epoch 内周期验证代码目前是注释状态。要确认实际验证频率，应看运行的 `valid(...)` 调用位置，而不是只看命令行里是否有 `eval_angouts` 参数。

## 4. 网络从入口到出口

### 4.1 `Net_CrossAttention.__init__`

主模型装配三个主要部分：

1. `ASRFeatureExtractor`：把输入 SAI 编码为 64 通道的角度/空间特征。
2. `FourVolumeFeatureRebuild`：由输入特征构建四个体积，体积交互、角度场合成，并用隐式解码器生成目标视角特征。
3. `DownSample`：用若干个 `1×1×1 Conv3d` 把每个像素位置的 64 维特征映射到 1 个灰度值。

这里名为 `DownSample` 的层不是把图像空间缩小；它作用于通道维度，将特征通道压成图像强度。

### 4.2 `Net_CrossAttention.forward(x, angout)`

按真实执行顺序：

```python
buffer = self.extract_lf_feature(x)          # [B,64,2,2,H,W]
buffer = self.epiFeatureRebuild(buffer, angout) # [B,64,N,N,H,W]
buffer = rearrange(buffer, 'b c u v h w -> b c (u v) h w')
buffer = self.DownSample(buffer)             # [B,1,N*N,H,W]
out = FormOutput(buffer, angout)              # [B,1,N*H,N*W]
out = self.copy_input_corners_to_sai(out,x,angout)
```

`FormOutput` 将视角序列重新拼成 SAI。最后复制四角，确保网络角视图的数值与输入完全一致。注意这个操作使用 `clone()`，避免直接覆盖某个仍被其他引用使用的张量。

### 4.3 `forward_view`

用于只生成单个目标视角的路径。若请求位置是四个角之一，直接从输入切片返回；否则提取特征，并调用隐式解码器的 `forward_view`，最后通过 `DownSample` 映射为单通道图像。它适合逐视角查询/调试，不等同于完整 SAI 的 `forward`。

## 5. 特征提取器：`ASRFeatureExtractor`

输入是拼接的 SAI。第一步按角度拆分成小视角布局，空间卷积只在单个视角的像素平面内做特征提取（3D 卷积的角轴 kernel 为 1，不直接跨邻接视角混合）。接着转成适合解耦块处理的布局，进入级联的 `CascadeDisentgGroup`。

`DisentgBlock` 的要点是让不同分支看不同结构：

- 空间分支提取单个视角内的纹理与更大感受野。
- 角度分支聚合/恢复角度格点上的信息。
- 水平和垂直 EPI 分支分别沿两个方向建模角度与空间共同变化。

多分支结果通过残差连接融合。残差的直观意义是模块主要学习“在输入特征上需要补充的变化”，避免深层堆叠时信息完全重写。

阅读这一段时尤其留意 `rearrange`、`view`、`permute`：它们把同一 SAI 从“按大图排布”切换到“把视角当作独立维度”。核尺寸、stride 和 PixelShuffle 必须与这些排列保持一致，否则输出维度会错位。

## 6. 四体积重建：为什么叫 `uvs / uvt / ust / vst`

光场可用四个坐标 `(u,v,s,t)` 表示：前两个是视角坐标，后两个是视角内部像素坐标。`FourVolumeFeatureRebuild` 不是直接从四维特征中丢掉信息，而是沿不同轴进行注意力池化，构造四种三轴特征体积：

| 体积 | 聚合掉的轴 | 保留的轴 | 便于理解的观察方向 |
|---|---|---|---|
| `uvs` | `t` | `u,v,s` | 两个角轴 + 竖直像素轴 |
| `uvt` | `s` | `u,v,t` | 两个角轴 + 水平像素轴 |
| `ust` | `v` | `u,s,t` | 一个角轴 + 两个像素轴 |
| `vst` | `u` | `v,s,t` | 另一个角轴 + 两个像素轴 |

`PlaneAttentionPool` 将待聚合轴上的 token 送入多头注意力，用一个可学习 query 汇总出该轴的表示。它比简单平均池化更灵活：模型可以学习哪些位置对当前体素更重要。

编码后的体积还会经过残差卷积块。可选的可学习模板在体积上直接相加，给模型一份可训练的初始结构先验。当前模板空间尺寸是固定的；模型输入的单视角空间尺寸若与模板不匹配，`_add_template` 会报错。这是使用模板时应优先核对的约束。

`add_coordinate_conditioning` 为特征加入 `(u,v,s,t)` 归一化坐标经 MLP 投影后的嵌入。直观上，卷积知道局部邻域，但卷积本身不直接告诉特征“我在整个光场的哪里”；坐标条件提供了绝对位置线索。

## 7. 体积交互与任意角度场

### 7.1 `VolumeAxialTransformerBlock`

对体积的每个轴分别做自注意力。轴向注意力将大规模 3D 全局注意力拆成多个沿单轴的注意力，减少 token 两两交互的开销。随后 FFN 对每个 token 做通道变换，并配合归一化和残差连接。

### 7.2 `FourVolumeSummaryTransformer`

四个体积先各自做轴向处理，再加入表示“体积类型”的 token，并把四个体积 token 与光场全局摘要放进跨体积注意力。这样 `uvs` 可以接收来自 `uvt/ust/vst` 的信息。较大的 `ust/vst` 会先池化到设定的空间网格，注意力处理后再插值回原始尺寸，以控制显存。

如果看到 `ablate_volumes` 或 `ablate_planes`，它是消融实验接口：指定支路被置零/关闭，用来对比某一类体积信息对结果的影响。

### 7.3 `CoordinateConditionedBasisFieldUpsampler`

这是输出角度数可变的重要模块。一般的固定尺度卷积会把输出大小写进网络结构；这里则学习一组空间基函数，再根据目标角坐标预测组合系数：

1. `basis_encoder` 从体积特征提取一组基函数。
2. `content_encoder` 将体积内容汇总成条件向量。
3. `_target_coordinates(angout, ...)` 依据本次请求生成目标角网格。
4. 坐标做 Fourier 编码，再与内容向量一起送给 `coefficient_decoder`。
5. `einsum` 将系数和基函数线性组合，产生指定角度位置的场特征。

因此 `angout` 决定要生成多少个角度位置，但不会改变这些层的参数形状。代码也会根据 `angout` 对坐标做物理范围缩放，使不同分辨率下的视角坐标具有一致含义。

## 8. 高斯解码器：从特征场得到缺失视角

当前四体积解码器是 `FourVolumeGaussianDecoder`。它对目标网格中每个非角点视角单独解码。

### 8.1 Anchor（锚点）是什么

四个输入角视角中的每个像素都可作为一个候选观测锚点。一个目标视角对应四组锚点像素，解码器为这些像素预测向目标视角贡献的高斯。

几何输入包含输入锚点角坐标、目标视角角坐标、二者位移、位移绝对值、角距离和方向。它告诉 MLP：“这个输入像素来自哪个角，当前要预测哪个角，两者相隔多远、方向如何”。

### 8.2 高斯参数 MLP

解码器将四种体积场上下文和 anchor 特征拼接，再与几何量拼接，送入 MLP。输出被拆成多个高斯参数：

- `delta`：相对锚点像素的中心偏移。
- `scale`：两个空间方向上的尺度，通常经指数映射保持为正。
- `rho`：两个方向相关项，限制在稳定范围内。
- `opacity`：贡献强度，经 sigmoid 约束到 0–1。
- `values`：高斯携带的特征向量，之后映射为图像特征。

偏移量可以按角距离自适应：目标角离输入锚点越远，可允许的搜索偏移越大。置信门控网络则给四个输入视角分配 softmax 权重。其末层零初始化，使训练初始时接近四路均匀权重，避免随机门控在训练刚开始就偏向某一角。

### 8.3 `_splat_gaussians`：把高斯落到像素网格

每个高斯在像素网格附近计算椭圆高斯权重，累加携带的特征值，同时累加权重归一化项；最终用累加特征除以累加权重，得到目标视角特征图。实现使用 `scatter_add_` 做散射累加。

为了约束计算量，代码仅在有限像素窗口中枚举贡献，并用半径上限限制最坏情况下的窗口大小；超过支持范围的贡献被裁掉。大量偏移会按 chunk 分批处理，降低一次性张量的内存占用。

### 8.4 四个角点的快捷路径

角点已经观测到，因此 decoder 对角点直接取输入特征/图像路径，不做高斯预测。完整输出阶段还会把四个原始灰度图块重新写入 SAI，确保角点像素级保持输入值。

## 9. 损失函数：只评价模型负责预测的视角

### 9.1 SAI 拆为视角：`missing_view_lf_tensors`

函数先检查预测和标签形状相同、SAI 高宽可被 `angout` 整除，再 reshape + permute 为 `[B,C,U,V,H,W]`。这样可以明确按角坐标选择视角，而不是在拼接大图上误把块边界当作普通连续像素。

随后创建 `[U,V]` 布尔掩码，把四个角置为 `False`，内部视角保持 `True`。

### 9.2 `missing_view_l1_loss`

只取 mask 为真的视角，并计算普通 L1（平均绝对误差）。也就是说角点不参与损失，因为角点已知且被硬拷贝；监督重点是模型生成的视角。

### 9.3 `missing_view_sobel_gradient_loss`

对缺失视角分别计算预测和标签的 Sobel 水平/垂直梯度，再用 Smooth L1 比较梯度。它鼓励边缘方向和局部纹理变化一致。Sobel 后裁去一圈边缘，避免零填充边界影响梯度监督。

### 9.4 备用损失

`missing_view_l1_loss_with_weights` 支持像素权重；`edge_weighted_missing_view_l1_loss` 可增加边缘区域权重。这两者在当前 `train.py` 核心训练循环中没有被调用，主损失是缺失视角 L1 加逐渐启用的 Sobel 梯度损失。

## 10. 验证、图像和指标

### 10.1 分块推理：`LFdivide` / `LFintegrate`

当测试图空间尺寸较大时，`LFdivide` 按空间块切分光场，并带边界扩展；模型对每个块独立推理后，`LFintegrate` 把块放回原光场位置。块之间有重叠，积分函数取每块的有效区域，减少边缘填充对结果的影响。

这些函数按每个角视图的小图空间切块，再保留所有角视图组合。阅读时要区分 `patch_size/stride` 是空间像素尺寸，不是角度分辨率。

### 10.2 `valid(...)`

验证循环通常会：

1. 从测试 batch 取输入与标签并送到设备。
2. 调用 `net(data, eval_angout)` 预测完整 SAI。
3. 在角度/空间布局下计算每视角 PSNR、SSIM，并汇总缺失视角结果。
4. 按开关保存预测与标签 PNG、每样本 CSV、逐视角诊断 CSV。
5. 汇总数据集级指标并返回。

验证代码还可读取 decoder 记录的高斯偏移、尺度、opacity、confidence、饱和比例等诊断字段。这些指标用于判断高斯是否长期顶到偏移上限、是否只依赖单一锚点等。

### 10.3 PSNR / SSIM 与边界裁剪

`cal_psnr`、`cal_ssim` 使用 NumPy/skimage 指标。逐视角评估通常先从 SAI 还原视角维度，再排除四角，并按当前代码约定裁掉边缘像素后计算。查看分数时应确认：评测是不是只覆盖缺失视角、是否裁边、输入标签方向是否一致。数据转置错误可能不会报错，但会让指标失去意义。

PNG 保存路径会将光场拆回视角网格或输出单张 Tensor 图像。`save_test_image_limit` 控制每个数据集/角度/epoch 保存样本数；负值表示不设上限。

## 11. 辅助文件逐个说明

### `training_policy.py`

集中处理训练策略，不负责模型计算：验证模式参数、固定/随机选取 `angout`、决定是否调用增强函数、生成结果标签字符串。把策略逻辑独立出来，训练循环就不必散布大量模式判断。

### `data_augmentation.py`

实现同步翻转、转置和逐视角中心放大。`_flip`、`_transpose_last_two_axes` 根据输入是 Tensor 还是 NumPy 调用对应操作。NumPy 双线性 resize 自己实现了 `align_corners=False` 风格的坐标采样，使无 PyTorch 的场景也可使用增强逻辑。

### `checkpoint_utils.py`

- `str2bool`：让命令行参数接受 `true/false/yes/no/1/0` 等写法。
- `clean_state_dict_key`：去掉 DataParallel 保存的 `module.` 前缀。
- `filter_pretrain_state_dict`：只接受键名和张量形状都兼容的模型参数。
- `build_training_checkpoint`：组装训练状态字典。
- `restore_scheduler_state`：有 scheduler 状态就完整恢复；旧 checkpoint 没有时按 epoch 对齐 `last_epoch`。

### `utils_append.py`

除 Dataset、在线裁切与损失外，还包含分块推理/积分和指标计算。`TestSetDataLoader` 是当前固定测试数据模式使用的 Dataset；同文件中的 `TestSetLoader`、`TestSetLoaderRawLF` 等旧接口需结合调用点判断是否仍被当前入口使用。

## 12. 读代码时的实用技巧

1. **先追调用，不先通读大文件。** 从 `main → train → net.forward` 跳转，比从模型文件第一行一路读到结尾有效。
2. **每遇到 reshape 就写下形状。** 例如 `[B,1,448,448] → [B,1,7,64,7,64] → [B,1,7,7,64,64]`。大多数难点都来自维度含义变化。
3. **找入口确认模块是否生效。** 类定义不等于被调用；查看 `__init__` 创建什么，`forward` 调用什么。
4. **把角度轴和像素轴区分开。** `angout` 控制视角网格，`H/W` 控制每个视角图像大小。
5. **跟着一个具体配置走。** 默认 `angin=2, angout=7, H=W=64`，比抽象读所有可选参数容易。
6. **遇到 `einsum`，先写输入每个字母代表什么。** 它通常是基函数与坐标系数的乘加，不要把它当成神秘层。
7. **训练和验证的数据格式分开检查。** 训练是完整原始光场在线裁切；验证是已配对的固定 `data/label`，并有转置约定。

## 13. 一页纸总流程

```text
训练 HDF5 原始 SAI（source_ang_res×source_ang_res 个视角）
  ↓ TrainSetLoaderRawLF
按本轮 angout 中心裁切 → label SAI
  ↓ 从 label 的四角抽出 2×2
data SAI + label SAI（同步增强）
  ↓ Net_CrossAttention
角度/空间特征提取
  ↓
沿四种轴注意力池化，构建 uvs / uvt / ust / vst
  ↓
体积内轴向注意力 + 四体积交互
  ↓
坐标条件基函数合成目标角度场
  ↓
高斯解码并 splat 出每个缺失视角特征
  ↓ 通道投影 + FormOutput
预测 SAI，复制四角输入图像
  ↓
缺失视角 L1 + warmup/ramp 后的 Sobel 梯度损失
  ↓ backward / Adam / StepLR / checkpoint
```

如果只记三个关键点：**数据在线从标签四角构造输入；网络的核心是四个三轴体积和按目标角坐标生成特征场；训练损失只监督未观测的视角。**
