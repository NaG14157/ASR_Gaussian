# ASR_Gaussian 流程

---

## 0. 速览

**这份代码只做一件事：给它 4 张角落视角的照片，它还你 49 张完整视角的照片。**

```
      输入                          网络                         输出
  ┌──────────┐              ┌──────────────┐              ┌──────────┐
  │ 2×2 视角  │  ────────→   │  8 个"车间"   │  ────────→   │ 7×7 视角  │
  │ 128×128  │              │  见第 3 节    │              │ 448×448  │
  └──────────┘              └──────────────┘              └──────────┘
     只有四个角                  中间全靠猜                  49 个齐全
```

- **空间清晰度不变**：每个视角始终是 64×64 像素，从头到尾没变过
- **变的是"视角数"**：从 4 个变成 49 个
- **要猜的是中间 45 个视角**（4 个角是已知的，最后直接抄回去）

这叫**角度超分**（Angular Super-Resolution）：不是把图片放大变清晰，而是**把从没被拍到过的视角补出来**。

---

## 1. 输入和输出

### 1.1 光场数据被拼成一张"大图"

这份代码里所有数据都是**一张大图**，规则是"第 (u,v) 个视角贴在哪个方块里"：

```
        v=0          v=1
    +------------+------------+
u=0 |  视角(0,0)  |  视角(0,1)  |   每个方块 = 一张 64×64 的小照片
    +------------+------------+
u=1 |  视角(1,0)  |  视角(1,1)  |   整张大图 = 128×128
    +------------+------------+
```

- `u` = 视角的**上下**编号，`v` = 视角的**左右**编号（合称"角度"）
- `s` = 视角内部的**行**，`t` = 视角内部的**列**（合称"空间"）

这种拼法叫 **SAI**。代码的输入和输出**都是**这种大图。

> 📌 顺手记一个坑：代码里的 `SAI` 指的是**这张拼接大图**，不是"单独某一个视角的照片"。虽然字面意思（Sub-Aperture Image）容易让人以为是后者。

### 1.2 为什么"视角"这么重要

想象你站在固定的位置，面前有一排窗户看菜市场：近处一个红苹果，远处一块蓝招牌。

- **换一扇窗户，苹果在画面里横移一大截**（近的视差大）
- **换一扇窗户，招牌几乎不动**（远的视差小）

**这个"横移多少"就是视差，而视差反比于距离。** 所以只要视角足够密，就能反推出每个物体有多远——这就是光场能算深度的原因，也是为什么"补出更多视角"是有意义的。

### 1.3 训练数据是怎么被切开的

训练文件里存的不是"47 张照片"，而是**一个 9×9 的完整光场**（大图 576×576）。训练时现场切：

| 步骤 | 做什么 | 结果 |
|---|---|---|
| 1 | 从 9×9 里**居中裁**出 7×7 | 大图 448×448 → **这是"标准答案"** |
| 2 | 取标准答案的**四个角**，拼成 2×2 | 大图 128×128 → **这是网络的输入** |

所以网络的任务非常明确：**看着四个角，猜出中间 45 个。**

> **测试时不一样**：测试文件是**提前切好的**，里面直接就有"2×2 输入"和"7×7 答案"两样东西，不再现场裁。

## 2. 训练一遍，机器里发生了什么

每一轮（epoch）里的每一步：

| # | 步骤 | 白话 |
|---|---|---|
| 1 | 读一个 9×9 光场 | 从硬盘取一个样本 |
| 2 | 决定这轮要几个视角 | 默认固定 7×7；也可以设成"3~9 之间随机抽" |
| 3 | 裁出"标准答案" | 居中裁成 angout×angout |
| 4 | 造"输入" | 把标准答案的**四个角**拿出来拼成 2×2 |
| 5 | 数据增强 | 左右翻、上下翻、转置；还有"中心放大"（只在固定尺度模式下开） |
| 6 | **前向**：网络出预测 | 128×128 进 → 448×448 出 |
| 7 | **算损失** | 只算中间 45 个缺视角的误差 |
| 8 | 反向传播 + 更新权重 | 标准训练动作 |
| 9 | 存 checkpoint + 写日志 | **每轮都存一个文件**，同时写 txt / CSV / tensorboard |

> ⚠️ **一个必须知道的事实**：训练循环里的"逐轮验证"被整段注释掉了。
> 也就是说 **训练过程中看不到 PSNR/SSIM 变化**，只在开训前跑一次验证。
> 想看某个 epoch 的效果，得单独加载那个 checkpoint、设 `--n_epochs 0` 跑一遍评估。

## 3. 网络内部：8 个"车间"

这是最核心的部分。用"办工厂"的比喻，数据从上游走到下游。

### 先看全流程的"尺寸变化表"

```
输入 SAI                    (1, 1, 128, 128)          ← 2×2 视角，每视角 64×64
   ↓ 车间 1  特征提取
特征                        (B, 64, 2, 2, 64, 64)    ← 64 通道//64 种网络学出来的抽象特征
   ↓ 车间 2  拆四个体积 + 车间 3 开会
uvs (B,64,2,2,64)   uvt (B,64,2,2,64)
ust (B,64,2,64,64)  vst (B,64,2,64,64)
   ↓ 车间 4  造"任意角度都能查"的场（这里查 7×7）
uvs场 (B,64,7,7,64)  uvt场 (B,64,7,7,64)
ust场 (B,64,7,64,64) vst场 (B,64,7,64,64)
   ↓ 车间 5 + 6  逐缺视角撒高斯（循环 45 次）
49 个视角的特征             (B, 64, 7, 7, 64, 64)
   ↓ 车间 7  压成单通道
                            (B, 1, 49, 64, 64)
   ↓ 车间 8  拼回大图 + 补回四角
输出 SAI                    (1, 1, 448, 448)         ← 7×7 视角
```

### 车间 1：特征提取 —— 把 4 张照片"嚼碎"

先把大图拆成 4 个视角，做**纯空间卷积**（角向不混，也就是只在单张照片内部做卷积），然后换成一种特殊排布，送进 **5 组 × 5 块**的"解耦卷积块"。

每个解耦块有 **6 条并行支路**，分别专攻：

| 支路 | 专攻 |
|---|---|
| 空间内 / 空间间 | 一张照片内部的纹理 |
| 角度内 / 角度间 | 视角与视角之间怎么变 |
| 水平 EPI / 垂直 EPI | 顺着"视差斜线"方向聚合信息（见 §4.4） |

**产出**：`(64 通道, 2, 2, 64, 64)` 的特征。

### 车间 2：拆成"四个体积" —— 把特征分成四份侧面清单

把四维数据 `(u, v, s, t)` 按"**每种扔掉一根轴的方式各做一份**"，正好 4 份：

| 体积 | 保留的轴 | 形状 |
|---|---|---|
| `uvs` | 视角行、视角列、纵向像素 | `(2,2,64)` |
| `uvt` | 视角行、视角列、横向像素 | `(2,2,64)` |
| `ust` | 视角行、纵向像素、横向像素 | `(2,64,64)` |
| `vst` | 视角列、纵向像素、横向像素 | `(2,64,64)` |

（"扔掉"不是真丢，而是用**注意力池化**把那根轴压成一个摘要。）

> 为什么是 4 个、为什么不能省？见 **§4.1**。

### 车间 3：让四份清单开个会

每个体积先沿自己的三根轴各做一次**自注意力**，然后**四个体积 + 一个全局摘要**拼在一起做一次"跨体积谈话"，散会后各自领回一份修正意见（`delta`）加回自己的报告。

> 为什么会用自注意力？见 **§4.1**。

### 车间 4：造一台"任意角度都能查"的机器

这是**"任意角分辨率"的秘密**：把体积变成一组**基函数**，再用"你想要的角坐标"**现算**出系数，合成出目标角分辨率的场。

> **关键**：角坐标是运行时算的，**不参与任何权重形状**。所以查 7×7 还是查 15×15 只是"查多密"，**不用重训**。

### 车间 5：对每个缺视角，撒一把"高斯小墨点"

对**每一个**缺失视角（45 个）单独执行：

**第一步，布"锚点"（anchor）。**
把"4 个输入视角 × 每个像素"当成一根根锚点。也就是说，一共 `4 × 64 × 64 = 16384` 个锚点，每个锚点代表"某个输入视角在某个像素上看到了什么"。

**第二步，每个锚点预测 4 个高斯。**
用 MLP 从"四个体积的上下文 + 锚点特征 + 几何量"里预测出 4 组参数，每组 **70 个数**。

**第三步，两个巧思：**

- **偏移上限随角距离自适应**：离输入视角近的锚点，允许它最多挪 8 像素；远的允许挪 16 像素。
  （远处视角视差大，需要更大的搜索范围）
- **置信度门控**：4 个锚点各给一个权重（softmax），谁更可信听谁的。

> 高斯的参数分别是什么、为什么是这些数？见 **§4.2**。

### 车间 6：墨点晕开，叠成一张图

每个高斯按**马氏距离**（可以理解成"高斯形状的权重"）把自己的特征扩散到周围一小片像素上，用 `scatter_add_` 累加，最后**除以总权重做归一化**。

三个实现细节：

| 细节 | 做法 | 为什么 |
|---|---|---|
| 枚举窗口多大 | 半径 = `ceil(3×最大的σ)`，**硬上限 2**（最多 5×5） | 控制显存和计算量 |
| 哪些点算数 | 只保留马氏距离 ≤ 9（3σ 支撑域）内的点 | 超出 3σ 的权重小到可忽略 |
| 显存怎么办 | 按 256MB 上限**自动分批**累加 | 防止爆显存 |

### 车间 7：压成单通道

三层 1×1 卷积把 **64 通道压成 1 通道灰度**。

### 车间 8：拼回大图 + 四角补回原图

把 49 个小视角按规则拼成大图，然后**把四个角直接换成原始输入的像素**——保证已知视角零误差。

## 4. 三个"为什么"

### 4.1 为什么要拆成四个体积？为什么会突然用自注意力？

#### 先问一个更根本的问题：为什么不能"直接把小图放大"？

普通超分（100×100 拉成 200×200）可以用插值。但这里要干的是**"发明"从来不存在的新视角**。

为什么难？因为**视差**。同一个苹果，在视角 (0,0) 里在左边，在视角 (6,6) 里在右边，而且不同深度移动幅度还不一样。所以新视角**不能靠插值糊出来**，必须有一个"**懂得场景三维结构**"的东西来算。

这就决定了：网络需要一个**能按任意角度坐标去"查询"的表示**。

#### 那为什么不直接用一个 4D 张量？

4D 特征张量有 `(u, v, s, t)` 四根轴，两个麻烦：

1. **两根角度轴要和两根空间轴"分别放大"很别扭**——它们缠在一起
2. 车间 4 要做的"造任意角分辨率场"，需要**角度轴是显式、可单独拉伸的**

#### 拆成四个，是为了"一网打尽四种视角"

从四根轴里**扔掉一根**，恰好只有 **4 种扔法**，所以正好得到 4 个体积——**不多不少，是一套完整的组合**。

> **比喻**：要描述一个立体雕像，你没法把"立体"塞进一张照片。但你可以拍**四张不同方向的侧面照**——每张都丢了一点信息，但**四张合起来**就能拼出立体感。
> （这个套路在别的领域叫 Triplane：三维数据拆成三张平面。这里是它在四维光场上的直接类比。）

四个体积各有专长：

| 体积 | 它擅长看什么 |
|---|---|
| `uvs` / `uvt` | **视角之间怎么变**（视差、EPI 结构） |
| `ust` / `vst` | **一整幅画面** + 一根角度轴 |

#### 而且——下游解码器正好要 4 份"证据"

车间 5 里，解码器对目标视角 `(u,v)` 取上下文时，**四个体积各取一份切片**：

```
uvs → 沿纵向的一条"剖面"
uvt → 沿横向的一条"剖面"
ust → 一整个二维面
vst → 一整个二维面
```

然后和锚点特征拼起来：`4 × 64 + 64 + 11 = 331` 维，喂给 MLP。

> **所以四个体积存在的直接理由就是：解码器需要四个"证人"，从四个不同的结构角度描述同一个光场，然后一起决定这个新视角长什么样。**

#### 那为什么会"突然"上自注意力？

因为这一步的任务**变了**。

车间 1 干的是"**抠局部纹理**"——那是卷积的强项（局部、平移不变）。
而车间 3 要干的是卷积**不擅长**的事：

| 要干的事 | 为什么卷积不行 | 注意力怎么解决 |
|---|---|---|
| **① 长轴上的全局关联** | `ust`/`vst` 是 `(2,64,64)`，3×3×3 卷积只能看见紧邻的几个点 | 轴向注意力让**任意两个位置直接对话**，感受野立刻变成全局，而且代价只要 O(n·L)，远小于全局注意力的 O(n²) |
| **② 四个体积互相核对** | 四个体积是**分开的张量**，卷积管不到彼此 | 把四份 token 拼在一起做一次"跨体积谈话"，各自再领回一份修正量 |
| **③ 分清谁是谁** | —— | 加了 **5 个"类型 token"**，告诉注意力"这枚 token 来自 uvs / uvt / ust / vst / 全局"，否则混在一起分不清 |

> **比喻**：车间 1 像流水线上的工人，各管一段。车间 3 像把**四位专家叫到会议室**：每人先讲自己那一路（轴向自注意力），然后集体讨论（跨体积注意力），散会后各自带回去一份"别人对我的修正意见"，加回自己的报告里。
>
> **这就是为什么文件名叫 `crossAttention`**——不是"为了用而用"，而是这一步的核心任务就是**让四份信息碰头对齐**。

### 4.2 高斯的 6 + 64 个参数是哪来的？分别什么意思？

#### 先想：一个"会晕开的墨点"，需要回答哪些问题？

```
         ◜‾‾‾◝
        (  ●  )      ← 一个高斯 = 一团会晕开的墨
         ◝___◞
```

它必须能回答 4 个问题：

| 问题 | 需要几个数 | 对应参数 |
|---|---|---|
| **我在哪？** | 2（纵向、横向） | `delta` 偏移 |
| **我多大、什么形状？** | 3 | `σ_s`、`σ_t`、`ρ` |
| **我多浓？** | 1 | `opacity` |
| **我携带什么内容？** | 64 | `values` |
| | **共 70** | |

#### 逐个讲"为什么是这个数"

**`delta`：2 个偏移 —— 为什么不能是 0？**
因为**视差**。目标视角里真正对应的那个点，**不在同一个像素位置上**，它必须能挪。如果只给锚点位置、不让挪，那视差大的地方全糊。

**`σ_s`、`σ_t`：2 个尺度 —— 为什么要两个？**
因为墨点**不是圆的**。一条边缘在新视角里的"拖影"往往是被**拉长的**，所以纵、横两个方向要能**分别伸缩**。

**`ρ`：1 个相关系数 —— 这个是关键。**
只有 `σ_s` 和 `σ_t`，你只能画出**正着的椭圆**（长轴横着或竖着）。加上 `ρ`，椭圆就能**歪着**：

```
   只有 σ 和 σ        加上 ρ
     ⬭   ⬮           ⟋   ⟍
   （正椭圆）        （倾斜椭圆）
```

数学上，二维高斯的形状是一个 2×2 协方差矩阵，它有 **3 个独立自由度**。`σ_s`、`σ_t`、`ρ` 正好凑齐这 3 个，**一个不多一个不少**。

> 所以"2 尺度 + 1 相关"= **一个完整的二维各向异性高斯**。

**`opacity`：1 个不透明度。**
就是"这个墨点有多浓"。因为同一个像素会被**很多个**墨点覆盖（4 锚点 × 4 高斯 = 16 个），需要一个相对权重来决定"谁说话更算数"。

**`values`：64 维特征 —— 为什么不是颜色？**
传统高斯泼溅里高斯带的是**颜色**。这里带的是 **64 维特征向量**，**它没有"颜色"的含义**，是个内容载体。颜色最后由车间 7 从这 64 维里压出来。

**为什么这么做？** 因为要让整个网络**端到端可训练**：颜色不是"优化出来的属性"，而是"网络算出来的输出"。

#### 这些参数是"参考谁"的？—— 三条血脉

| 参数 | 来自哪条路线 |
|---|---|
| **位置 + 尺度 + 透明度** | **高斯泼溅（3DGS）**：位置(3) + 协方差(尺度3+旋转4) + 透明度(1) + 颜色(球谐 48)。本项目把它从 3D 压到 2D |
| **用 `(σ_s, σ_t, ρ)` 表示形状** | **二维各向异性高斯的经典写法**（图像处理里的老手艺） |
| **"用 MLP 从特征+坐标预测参数"** | **隐式表示路线**（LIIF、NeRF）：把"输出颜色"换成了"输出高斯参数" |
| **值是 64 维特征而非颜色** | **特征泼溅**的思路，为的是前馈式、可端到端训练 |

#### 最后：为什么每个参数前套了不同的函数？

这不是随便选的，都是在**保证数学合法性**：

| 参数 | 套的函数 | 为什么 |
|---|---|---|
| `delta` | `tanh` | 偏移必须**有界**（有意限制搜索范围）。而且用乘法形式让梯度**永远不为零**，不会有"卡死的高斯" |
| `σ` | `exp` | σ 必须 **> 0**（尺度不能是负的） |
| `ρ` | `tanh × 0.95` | 协方差正定要求 **\|ρ\| < 1**，乘 0.95 留安全边界 |
| `opacity` | `sigmoid` | 要当权重用，压到 **(0,1)** |

### 4.3 是重建 3D 场景再取视角，还是直接在 2D 图片上渲染？

#### 明确回答：**直接在二维图片平面上用 2D 高斯渲染。完全没有 3D 重建。**

四条硬证据：

| 证据 | 说明 |
|---|---|
| **① 高斯的位置就是像素下标** | `center_s`、`center_t` 是**目标视角图像里的行、列**，不是三维坐标 |
| **② 协方差是 2×2** | 只有 `σ_s`、`σ_t`、`ρ`，**没有第三个维度** |
| **③ 泼溅结果是二维特征图** | 累加进 `(通道, 高×宽)`，就是一张图 |
| **④ 没有深度、没有相机位姿、没有投影** | 全文件搜不到任何相关量 |

还有一个**决定性旁证**：

> **它不做深度排序。** 传统 3DGS 渲染必须按深度从远到近排序再做 alpha 合成——这是"从三维场景往某个视角看"的固有动作。
> 而这里用的是 `scatter_add_` **求和再归一化**。求和是可交换的，**顺序完全不影响结果**——说明这里根本不存在"谁遮挡谁"的概念。

#### 那"三维信息"去哪了？

**被隐式地学进了网络里**，而不是被显式地建出来：

- 四个体积 + 几何特征（目标角坐标、输入角坐标、偏移量、**角距离**、方向）一起喂给 MLP
- MLP 自己学会："对于这个目标视角，这个点应该往哪挪、挪多少、晕多开"
- 视差、遮挡的推理**全部编码在这套映射里**，没有一个显式的三维点云或深度图

> **比喻**：它不是"先搭一个真实的菜市场模型，再从新窗口看过去"，而是"**一个经验老到的速写画家**，看过四个窗口，直接凭感觉在纸上把每个新窗口该看到什么画出来"。他脑子里有立体感，但纸上没有三维模型。

#### 一个重要的诚实补充：这样做的代价

因为是**每个视角各自独立地**在二维平面上泼溅，所以：

> **"同一个物点在不同视角之间必须一致"这件事，不是靠一个统一的三维场景强制保证的，而是靠"共享四个体积 + 45 个视角的监督"隐式逼出来的。**

这意味着理论上可能出现**角度闪烁**（相邻视角之间轻微抖动），因为没有几何约束把它们锁在一起。这是这类"逐视角二维泼溅"方案的固有特点（显式三维重建的方案天然有跨视角一致性）。

这一点值得在实验里专门看一眼：把 45 个预测视角做成小动画，看有没有抖动。如果论文里要强调"任意角分辨率"，这很可能是审稿人会问的点。

### 4.4 补：EPI 和"视差补偿"是什么（车间 1 那两条支路）

车间 1 里有两条支路叫"水平 EPI / 垂直 EPI"，值得单独说一下。

**做法**：拿一排窗户，从每扇窗户的照片里，在**同一个高度**横着切一条极细的横线，然后把这几条线**从上到下叠起来**。叠出来的这张长条图就是一张 **EPI**。

**你会看到什么**：场景里**每一个物点都会留下一道"拖影"**：

- 近处物体换视角横移多 → 拖影**躺得很平**
- 远处物体几乎不动 → 拖影**几乎是竖直的**

**所以 EPI 上那道斜杠的斜率，就是视差，而视差反比于深度。** 它把一个"三维深度问题"变成了"二维图上一根线的倾角问题"。

**价值**：只要**沿着拖影的方向做卷积**，就能把同一个物点在不同视角下的信息**对齐着累加**——这叫**视差补偿**。不顺着拖影走，就会把不同物体的信息混在一起，出重影。

> 这就是几乎所有光场角度超分方法的核心 trick。代码里的 `HEPIConv` 用的是 `1×(2*angRes+1)` 的细长横条卷积核，扫的就是这个方向。

## 5. 损失怎么算

```
总损失 = 缺视角 L1  +  λ × 缺视角 Sobel 梯度损失
```

| 项 | 作用 |
|---|---|
| **缺视角 L1** | 只算 45 个缺视角的绝对误差，四个角不参与（它们本来就已知） |
| **Sobel 梯度损失** | 对缺视角算边缘梯度误差，补纹理细节 |

**梯度损失的引入有节奏**：前 **30 轮是 0**（先让它把大结构学稳），再用 **20 轮线性升到 0.05**（再补细节）。

## 8. 读者可能会问的问题

### Q1：那 64 维特征到底是什么？是位置/纹理信息吗？

**不是。** 它是一个**网络自己学出来的抽象编码**，没有任何人工赋予的含义——你没法指着第 7 维说"这是纹理"或"这是位置"。

三点具体说明：

1. **位置不在里面**。位置由单独的 `delta`（2 个数）承担。MLP 虽然会把几何量当输入（所以这 64 维**会跟位置相关**），但架构上没有理由让它重复携带位置。
2. **它也不叫"纹理特征"**。它的**职责**是"携带这个高斯要往目标像素上泼的内容"。至于这 64 个数内部怎么分工，是训练**涌现**出来的——通常会自发分化出一部分管亮度、一部分管边缘/结构、一部分管"这个信息来自哪个输入视角、可不可信"，但**这些角色是纠缠的、不可解释的**。
3. **为什么是 64？** 不是"因为要装 64 种信息"，而是因为**它必须和主干特征通道数一致**——否则泼溅出来的特征图接不回后面的压缩层（那一层要求输入正好 64 通道）。

   更准确地说：高斯特征维度和主干通道数**本来就是同一个超参数**（代码里都叫 `channel`，写死 64），**不是两个独立的选择**——改其中一个就等于改另一个。所以 64 是个**结构上的对齐要求**，跟"要装几种信息"无关。

想真正搞清它们，得**事后做实验**（对某些通道做可视化、做探针或降维），而不是读代码。
类比：问"ResNet 第 37 层第 12 个通道是什么"——你大致能说它响应某类纹理，但没法给它贴一个"位置"或"纹理"的标签。

### Q2：为什么是四个体积，不是两个、六个？

因为"从四根轴里扔掉一根"**恰好只有 4 种扔法**：

```
扔 u → vst     扔 v → ust     扔 s → uvt     扔 t → uvs
```

所以四个是**唯一能覆盖全部三轴组合**的数量。两个会丢信息，六个则是重复（不存在第五种扔法）。

### Q3：为什么没有深度排序也能渲染？

因为**这里的"高斯"不是三维场景里的物体**，而是"某个目标视角图像平面上的一团特征"。既然没有前后关系，就不需要排序。

传统 3DGS 要排序，是因为它真的在渲染一个三维场景（远的先画、近的后画、按透明度混合）。这里用的是**加权求和再归一化**——求和可交换，顺序无所谓。

### Q4：这套东西和 NeRF、普通卷积网络什么关系？

- **和普通卷积网络**：车间 1 就是标准的卷积特征提取（那部分你完全可以按普通 CNN 理解）
- **和 NeRF 的相似处**：都是"**把答案写成一个函数，然后按坐标去查询**"，所以能做到任意分辨率
- **和 NeRF 的不同处**：NeRF 查询的是"一个点的颜色和密度"，这里查询的是"**一组高斯参数**"；NeRF 要靠体渲染积分，这里靠泼溅求和

### Q5：训练时为什么看不到指标？

因为训练循环里的逐轮验证**被整段注释掉了**，只在开训前跑一次。想中途看效果，得单独加载某个 checkpoint 跑一次评估。**长训练的时候要特别注意这一点**，别以为它在默默评估。

### Q6："任意角分辨率"是它的卖点，为什么默认配置训不出来？

因为默认用的是**固定尺度模式**（只训 7×7）。模型只见过 7×7，自然不能指望它泛化到别的角度。

**想让它真能泛化，必须切到"任意尺度模式"**（每轮随机抽一个目标角度做训练）。换句话说：**默认参数并不在训练它宣称的能力**——这是最容易被忽略的一点。

### Q7：为什么 `batch_size = 1` 也能训？

因为**单个样本内部的信息量就很大**：一个样本里有 `4 × 64 × 64 = 16384` 个锚点，每个锚点又预测 4 个高斯。所以梯度信号完全够用，不靠"一批多张图"来凑。

### Q8：σ 的物理含义是什么？

**模糊程度 / 影响范围**。σ 越大，这个墨点晕得越开、影响越多像素；σ 越小，它越像一个锐利的点。

它之所以需要**学**，是因为"一个物点在新视角里应该有多大范围"取决于很多因素（视差大小、遮挡、纹理），没法手写公式。

### Q9：为什么用"锚点（anchor）"而不是直接预测？

**为了省事、也为了有依据。**

如果不设锚点，网络就得凭空决定"新视角里每个像素该长什么样"。而设了锚点之后，网络只需要回答一个**容易得多**的问题："**输入视角里这个像素的内容，应该挪到新视角的哪里、晕多大、多浓**"。

换句话说：**从"无中生有"变成"搬运+微调"**，这是个聪明的降难度设计。

### Q10：45 个视角是一个个循环算的，能不能并行？

**代码里是循环**（对每个缺视角单独走一遍解码 + 泼溅），所以耗时随角分辨率的**平方**增长——目标角度从 7 涨到 15，缺视角数从 45 涨到 221，差不多 5 倍。

理论上可以并行（把 45 个视角当成 batch 维），但显存会翻很多倍。**目前没做这个优化**，所以"任意角分辨率"的代价是耗时快速增长。

## 9. "初稿"状态

### ❌ 缺的东西

1. **数据准备脚本不在这个目录**——训练/测试用的 `.h5` 是怎么生成的没人知道，而且这两处的**转置约定还不一致**
2. **没有独立评估脚本**，只能靠"训练脚本 + 0 轮"的副作用来评估
3. **没有依赖清单**，而 PyTorch 版本敏感（旧 checkpoint 反序列化、σ 参数化都踩过坑）
4. **训练中途没有验证**

### ⚠️ 三个真实的技术风险

**① 空间尺寸被硬锁在 64。**
四个体积里加了一个"可学习基线模板"，形状是写死的。只要单视角空间尺寸不是 64，就会直接报错。想换分辨率必须改这里或关掉模板。

**② σ 的枚举窗口有硬上限（5×5）。**
作者在注释里承认：当 σ 大于约 0.67 时，3σ 支撑域会被切掉一部分（靠归一化补偿，属"可控退化"）。注释说实测 σ 收敛在 0.5 左右，所以**在收敛区间是精确的**——但这是**依赖实测**的假设，换个数据集未必成立。

**③ "任意角分辨率"默认不成立**（见 Q6）。

### 🗑️ 另有约 900 行死代码

文件名里那些 `FourPlane*`、`EpiFeatureRebuild`、`GaussianVolumeRasterizer` 等都是历代实验残留，**没被使用**。其中"四平面版本"和"四体积解码器"的形状约定**不自洽**——如果你不小心把主网络里的四体积组件换成四平面版本，**会崩**。别动那个地方。

## 10. 名词

| 名词 | 一句话解释 |
|---|---|
| **光场 / 4D 光场** | 不只记"多亮"，还记"从哪个方向来"的数据。四个坐标：角度 `(u,v)` + 空间 `(s,t)` |
| **SAI** | 把很多视角拼成一张大图。**本代码里指这张大图**，不是单张视角照片 |
| **视角 / 子孔径图** | 从某一个位置看到的一整幅画面 |
| **视差** | 换一个视角，同一个物点在画面里横移了多少（单位：像素）。视差反比于深度 |
| **EPI** | 把"一排视角"和"一条画面横线"交叉摊开的一张图。物点在里面是一条斜杠，斜杠的斜率就是视差 |
| **anchor（锚点）** | "某个输入视角的某个像素"。网络以它为起点，预测内容该挪到哪儿去 |
| **高斯 / 墨点** | 一团按二维高斯形状晕开的东西，携带 64 维特征。这里它活在**目标视角的图像平面**上（2D，不是 3D） |
| **泼溅（splat）** | 把高斯按权重"拍"到画布上、累加起来的动作 |
| **隐式场** | 把数据表示成一个"能按坐标查询的函数"，而不是一张固定网格。所以能做到任意分辨率 |
| **缺视角** | 49 个视角里，除 4 个已知角之外的 45 个要预测的视角 |
| **EPI 卷积 / 视差补偿** | 沿着 EPI 上的斜杠方向做卷积，把同一物点的信息对齐累加 |
